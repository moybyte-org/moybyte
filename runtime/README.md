# Moybyte userland runtime (host reference)

The **shared console** every target runs: the host simulator, the four console
boards and the browser build stage or freeze these files. On the host it sits over
`runtime/host/host_canvas.py` and the native kernels in `native/moy_gfx`, with no
device required, so it is the fast dev loop.

## The folders

| folder | what lives there |
|---|---|
| `shell/` | the console kernel: `console` and its `console_*` bases, `chrome`, the layer stack and the bars, the shell's stores and services, the input state |
| `wm/` | the window managers: `wm` (the small screen's back stack), `wm_windowed` and its `wm_*` parts |
| `toolkit/` | the draw toolkit: the public UI API (`ui`), `ui_draw` and its `ui_*` halves, widgets, layouts, fonts, icons, the clock (`ticks`) |
| `home/` | the home: `launcher_layer` and its `home_*` parts |
| `system/` | the system's own surfaces: Settings, the bar's popovers, the perf HUD, update, about, achievements, licences, the web console, the wallpaper, QR |
| `apps/` | the built-in apps: calc, files, get carts, paint, my art, the storybook, appearance, the text console |
| `editors/` | the Editor: the `editors_*` cores, the `editor_*` tabs and panes, the code, paint and cards layers, the theme editor, the project, the block compiler |
| `carts/` | the `.moy` store and the cart formats: the catalogue, seed, index, journal and sync, packs and documents, the picture formats |
| `run/` | running a cart: the Player, the cart API, the Lua tier's shared half, audio |
| `boot/` | the device boot spine (`device_boot`, `boot_carts`) and the dev channel |
| `host/` | the host's own, never staged: the ctypes bindings, the host's native library, the simulator glue |

The root holds the package (`__init__.py`) and this file.

**Folders.** runtime/ is ONE flat module namespace kept in folders: a board
stages every module flat into `modules/` (`tools/board_config.py`), so `import
console` names one module wherever its file sits, and `runtime/__init__.py`
spans the package path over every subfolder, so `runtime.<name>` does too. A
basename exists once in the tree, `device/` included; the stager refuses a
second. **`host/`** holds the modules no board stages, by where they live: the
ctypes bindings to the native kernels (`*_binding.py`, `moy_input`,
`moy_loop`, `moy_play`, `moycore`, with their C shims `moyhost_*.c`), the
host's one library and its compile body (`host_native`, `native_build`), the
compiled-cart runner (`wasm_host`), the boards' canvas on CPython
(`host_canvas`) and the simulator glue (`host_app`). The rows below name a
file by its basename, and so does code that reads one: a test or a tool takes
its path from `board_config.runtime_file(name)`, a CPython process importing
the staged modules bare puts `board_config.runtime_dirs()` on its path, and a
MicroPython driver puts `tests/unix_mp.py`'s `runtime_tree()`, runtime/ staged
flat as a board stages it, on its own.

## What's here

**The shared console (host == device).** The launcher/desktop/cards/code/paint UI is
one codebase the host and every board run; on a 320×240 board the host renders the
same pixels with the same petme128 font. Since the **2026-07 shell** refactor
(`docs/shell_ux_v1.md`) the console is everything-is-a-process: `console.py` is the
**kernel** (compositor/router — the `frame`/`handle_input`/`handle_pointer` loop over
a z-ordered Layer stack + the shared draw toolkit), the apps it runs live in
`project.py`/`player.py`/`editor_app.py`, the back-stack window manager in `wm.py`,
and each **surface is its own `*_layer.py` module** (the `Layer` protocol + the
extracted editors below). The files split into **shared** (canonical here,
build-staged into the firmware `modules/` tree so the device freezes the identical
code) and **host glue**.

## Run it

```bash
# interactive workstation (needs a display): boots to the launcher
#   arrows move, RUN=Enter, MENU=M, CODE=C, SAVE=S, HOME=H, quit=Esc
python tools/simulate_desktop.py

# headless demo tour -> animated GIF (launcher -> carts -> Make-it-mine)
python tools/simulate_desktop.py --demo --gif demo.gif

# launch a single cartridge directly (skip the launcher)
python tools/simulate_desktop.py --cart system_carts/moybyte.star_catcher.moy

# headless custom script
python tools/simulate_desktop.py --gif out.gif \
    --script "wait:20 right run wait:40 home wait:8 right run wait:40"
```

Script tokens: a button name (`menu/up/down/left/right/run/save/code/home`)
presses once; `name:N` presses then observes N frames; `wait:N` observes N frames.

## Why indexed + language-neutral

The canvas works in **palette indices** and the drawing API is plain
functions over a buffer — no dependency on `framebuf`, LVGL, or even Python in the
contract. That's deliberate: the same surface maps onto the device's native
`moy_compositor` RGB565 framebuffer (indices → RGB565 via the palette), and onto the
Lua VM the boards ship (#67). Cartridges are portable; only the backend changes.
